# 11. REST CRUD API

A complete REST API for notes, built on the whole field-tag stack:
`std/orm` for persistence, `json.MarshalStruct`/`UnmarshalInto` for the
wire format, and `std/web` for routing. One struct drives everything —
no DTOs, no mapping layer.

## What it demonstrates

- **Field tags doing double duty** — `[db(pk,auto)]`, `[column(name=…)]`
  and `[json(name=…)]` coexist on the same struct; the ORM reads the
  first family, the JSON marshaler the second.
- **A real CRUD surface** — list/get/create/update/delete over
  `GET|POST|PUT|DELETE /notes[/:id]` with correct status codes
  (201/204/400/404).
- **Merge-style updates** — `PUT` unmarshals the body over the loaded
  row, so absent keys keep their stored values.
- **Id safety** — a client-supplied `id` is never honoured; the
  primary key is always generated by `INSERT` + `last_insert_rowid()`.
- **In-process handler tests** — `api_test.skink` drives the real
  router through `types.NewRequest` + `ServeHTTP` against an
  in-memory database; no socket needed.

## Layout

```
code/
  main.skink      — entry point: opens notes.db, serves :8080
  api.skink       — Note struct, handlers, route table
  api_test.skink  — handler tests through the real router
```

## Build and run

```sh
cd code
skink -o notes_api main.skink
./notes_api        # listening on :8080, stores to ./notes.db
```

```sh
curl -X POST localhost:8080/notes -d '{"title":"buy milk","body":"2 pints","pinned":true}'
curl localhost:8080/notes
curl -X PUT localhost:8080/notes/1 -d '{"pinned":false}'
curl -X DELETE localhost:8080/notes/1
```

## Tests

```sh
cd code
skink -t api_test.skink
```

Five tests cover the create/get/list roundtrip, merge updates, delete,
error paths (malformed JSON, missing title, bad id, missing row,
unknown route), and forged-id rejection.
